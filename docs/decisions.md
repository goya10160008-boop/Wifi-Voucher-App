# Decisions

The 20 design decisions are in `docs/superpowers/specs/2026-10-25-voucher-manager-design.md` section 8. This file logs decisions made while building.

## 2026-10-25

1. **Omada PDFs have no text layer.** The sample (`samples/3HRS_10202026.pdf`) is a browser "print to PDF" whose glyphs are outlined vector paths, so `pdfjs-dist` `getTextContent()` returns nothing. `lib/pdf-text.ts` tries the text layer first, then renders each page and runs OCR (`tesseract.js`, digits only, 2x scale). On the sample it read all 56 codes correctly. The preview/untick step stays the safety net. Paste/CSV also works.
2. **OCR assets are self-hosted.** `scripts/copy-ocr.mjs` (runs on `predev` and `prebuild`) copies the tesseract worker, the three `-lstm` core builds, `eng.traineddata.gz` and the pdf.js worker into `public/` (git-ignored). No CDN at runtime. They are static assets, so they do not count toward the 3 MiB Worker limit.
3. **Code format:** `parseCodes` accepts only 6 to 10 digit numeric tokens (confirmed from the sample: 6 digits). The DB regex stays wider (`[A-Za-z0-9-]{4,32}`). If Omada ever issues alphanumeric codes, widen `lib/parse-codes.ts` and add a fixture.
4. **No real-PDF text fixture.** The spec asked for a parse test on real Omada PDF text. There is no text, and the sample holds real unsold codes (git-ignored). `tests/unit/parse-codes.test.ts` uses synthetic OCR-shaped text. The real sample is covered by the Playwright test (needs login).
5. **Hours, not minutes, in the plan form.** Stored as `duration_minutes`. Fractions work (0.5 h = 30 min).
6. **Icons are generated** by `scripts/make-icons.mjs` (see decision 15 for the current A&B mark).
7. **Local DB tests not run.** No Docker on the dev machine. The RPC logic was checked on the remote project inside a transaction that always rolls back (FIFO, idempotent retry, insufficient cash, out of stock, import counts, void burns code, Manila 23:59/00:01 buckets all passed). **Not tested:** true parallel `SKIP LOCKED` (needs two connections). Test it before relying on two sellers at once.
8. **Worker size:** about 2.47 MiB gzipped on 2026-10-25 against the 3 MiB free limit. Watch it when adding dependencies. Server code must not import `pdfjs-dist`, `tesseract.js` or `qrcode.react`.
9. **`proxy.ts` works under OpenNext** (`x-proxy: 1` seen in `npm run preview`), so no `middleware.ts` fallback is needed.
10. **Generated DB types** live in `lib/supabase/database.types.ts` (hand-trimmed from the generator). Regenerate after every migration.

## 2026-10-25: Mint redesign

11. **Design = "Mint"** (chosen by the owner from 5 samples). All colors, radii, shadows and fonts are tokens in `app/globals.css` (`@theme`). Pages use the shared classes (`.btn`, `.btn-ghost`, `.btn-danger`, `.field`, `.card`, `.alert-*`, `.tile`, `.pick`, `.chip`, `.row-link`, `.skeleton`); do not add per-page colors. Only two literal colors remain, both unavoidable: `themeColor` in `app/layout.tsx` and the QR `fgColor` in `components/VoucherCode.tsx` (keep them equal to `--color-pri` / `--color-ink`).
12. **Fonts** DM Sans + DM Mono via `next/font/google`: downloaded and self-hosted at build time, no font CDN at runtime. The build needs internet once.
13. **Animations are pure CSS** (keyframes in `globals.css`): press scale on buttons/tiles, `.code-card` slide-up, `.pop` for "Copied", `app/(app)/template.tsx` page fade (a template remounts per navigation), `.alert` slide-in, `.btn[aria-busy=true]` spinner (set `aria-busy={pending}` on submit buttons), nav pill slide (`--n`/`--i` CSS vars), `.skeleton` shimmer via `loading.tsx` (`(app)/loading.tsx` generic, `sales/loading.tsx`). A `prefers-reduced-motion` block at the end of the file shortens all of them to ~0. No animation library.
14. **Nav** is a client component (`usePathname`) so the active pill can slide between routes. Icons are inline stroke SVGs, decorative (`aria-hidden`); the text label names the link.
15. **Logo** drawn by `scripts/make-icons.mjs` (white WiFi arcs + "A&B" pixel text on `#166534`, 3x3 supersampling). Maskable icon keeps the mark inside the central 60%. Rerun the script after changing it.
16. **Concurrency tests** `supabase/tests/concurrency.test.ts` (single sells) and `supabase/tests/cart.test.ts` (cart sells; apply 0002 too) (4 cases: 20 parallel sells on 10 codes, 5 parallel same-key calls, voided code never resold under 20 parallel sells, two plans do not block each other) needs a LOCAL DB; skipped when `SUPABASE_TEST_DB_URL` is unset. It inserts and deletes rows with a throwaway owner, so never point it at the production project. **Run locally without Docker** (verified 5/5 runs, 4/4 passing, Postgres 18.4): in a scratch dir `npm i embedded-postgres` (real PG binaries; not a repo dependency), start it with `new EmbeddedPostgres({databaseDir, user:'postgres', password:'postgres', port:54329, persistent:false})`, `initialise()`, `start()`, `createDatabase('voucher_test')`; apply `supabase/tests/local-shim.sql` then `supabase/migrations/0001_init.sql` (unmodified) with any pg client; then `SUPABASE_TEST_DB_URL=postgresql://postgres:postgres@127.0.0.1:54329/voucher_test npx vitest run supabase/tests/concurrency.test.ts`. With Docker: `supabase start`, URL `postgresql://postgres:postgres@127.0.0.1:54322/postgres`. The shim only fakes roles, `auth.users` and `auth.uid()`; it does not prove PostgREST, real RLS-as-`authenticated` behaviour (the test connects as superuser) or Supabase pooler behaviour.
17. **Worker size** after the redesign: 2,614,752 bytes gzipped (about 2.49 MiB of the 3 MiB free limit).
18. **Not visually reviewed:** the logged-in screens (Home, Sell, Sales, Plans, Import, Settings, code screen) have not been looked at in a browser, because no owner login existed in the dev environment. `/login` was checked at phone and desktop width. Review the rest with a real login and report anything off.

## 2026-10-25: Independent review fixes

19. **Review result:** no Critical findings; DB grants/RLS/definer functions verified. Six Important findings fixed in the app (no DB change):
    - Totals and the CSV backup were exposed to the API's 1000-row cap. The export now pages with `.range()`; the Sales grand total comes from month buckets.
    - Query errors were shown as zeros. Home and Sales now throw to the error page; the export returns 500; archive/restore throws on a name clash.
    - E2E login waited for a heading that no longer exists, and the voided-total assertion was a tautology. Both fixed (still skipped without `E2E_EMAIL`/`E2E_PASSWORD`).
    - Lost sell response then plan change: the message now says the sale may already be recorded and links to Sales (the key is deliberately not rotated).
    - Same-key retry on the last code could say "out of stock" while the first call was committing. `sell` re-checks by idempotency key on OUT_OF_STOCK and redirects to that sale.
    - OCR: the text-layer check now needs 3 code-shaped tokens (a header date no longer skips OCR), the worker is always terminated, the render size is clamped, and the preview warns that OCR can misread a digit.
20. **Small fixes:** `isDate` rejects impossible dates (`2026-13-45`) instead of crashing; sales list has an `id` tiebreak; CSV guard covers leading tab/CR, adds BOM and `no-store`; security headers (`frame-ancestors 'none'`, `nosniff`); voided rows say "(voided)".
21. **Deferred (needs a DB migration or the owner):** the `payments` SELECT policy has no `active` check for staff (a deactivated staff user could read their own payment rows until the JWT expires); `plans.sort_order` is unused but harmless; turn on "leaked password protection" and asymmetric JWT keys in the Supabase dashboard; the 12-digit merged-token case in OCR is still dropped silently (the preview count check is the guard).

## 2026-10-25: Multi-voucher (cart) sales

22. **A cart is N ordinary sales rows, not a new "order" table.** Migration `0002_sell_cart.sql` adds `sales.group_id` (= the client's idempotency key) and `sales.seq` (1-based, unique per group; both NULL on old rows, enforced together by a CHECK). Void, totals, history, RLS and the CSV all keep working per code. `sell_cart(p_group_key, p_items jsonb, p_tendered_centavos, name, room)` returns the group's rows. Max 10 vouchers per sale across all plans; the same plan listed twice is merged; codes are assigned plan by plan in plan-id order, FIFO inside a plan, so `seq` is not the on-screen order.
23. **Carts are serialised per plan** with `select ... from plans where id = any(...) order by id for no key update`, taken before stock is counted. Reason: with only `SKIP LOCKED`, two carts each needing 2 of the last 2 codes can each skip the row the other holds and both fail although stock existed, and a cart behind one that rolls back reports a false OUT_OF_STOCK. Locking plans in id order also rules out deadlocks between mixed carts. `NO KEY UPDATE` does not block the foreign-key checks of single `sell_voucher` calls. `SKIP LOCKED` stays on the voucher pick (it still protects against single sells). Local mutation checks (PG 18.4): removing the plan lock fails "a cart waiting behind another cart that rolls back"; removing the existing-group re-check fails the same-key tests; removing all locks fails the parallel carts; LIFO fails the FIFO tests. Removing `SKIP LOCKED` alone does not fail any test: on current Postgres the LIMIT sits above the lock step, so a blocked reader re-scans to the next row. It is a wait-time optimisation, not a correctness need.
24. **Cash is stored once**, on the `seq = 1` payment (`tendered_centavos` = all cash handed over; the check `tendered >= amount` still holds). Change shown = tendered minus the sum of the group's prices (voided rows included, since the guest paid at the original total). One cash payment row per code, as before, so voiding one code voids only its payment.
25. **Idempotency** = the group key. Per-row keys are `md5(group_key || ':' || seq)::uuid`, so a retry returns the same rows (even after stock ran out or a plan was archived) and the same key with different items is `KEY_REUSED` (also if a different user presents the key). The existing-group check runs after the plan locks so a concurrent same-key call waits and then returns the first call's sale instead of OUT_OF_STOCK.
26. **All sales now go through `sell_cart`** (a single voucher is a cart of 1 and still redirects to `/sales/[id]`). `sell_voucher` is untouched and still tested but unused by the app; remove it in a later migration if wanted.
27. **Migration 0002 must be applied to the remote project before the new Sell page works.** Until then the page shows "The database is missing the cart update (migration 0002)". Local `npm run dev` talks to the same remote database.
28. **Found by the new tests:** a cart item with a missing `plan_id` slipped past the shape check (NULL inside `bool_or` is ignored) and failed later as PLAN_NOT_FOUND. Fixed with `coalesce(..., false)`.
29. **Known limits:** the Sales list groups rows within the 50-row page it fetched, so a cart can be split across a page boundary (each row still opens correctly). Item errors for a short plan come back as `OUT_OF_STOCK` with DETAIL "<plan>|<codes left>" and are shown as "Only N codes left for <plan>". The logged-in UI (cart, group page, Copy all) has not been looked at in a browser.
30. **Worker size** after the cart: 2,623,810 bytes gzipped (about 2.50 MiB of the 3 MiB free limit), measured with `npx opennextjs-cloudflare build` from the project root.
