# Stage 1: who sold, staff wording, hardening, activity log

Source: `2026-10-25-staff-accounts-plan.md` sections 4, 5 and 7 (v1 only). Branch `feat/stage1-log`. No PIN login, no login events (later stages). Nothing here is applied to the remote database: `0003_hardening_and_audit.sql` is a file until the owner approves.

## How it will work (plain words)
- The owner sees **who sold** each code (name next to every row, on the group and sale pages, and a `seller` column in the CSV). Staff only ever see their own sales, so they see no extra names.
- Staff see "Your sales today / this month / total" so they know the numbers are only theirs. The owner keeps the shop-wide wording.
- A new owner-only **Logs** page lists what happened, newest first, as plain sentences ("Maria sold 3 vouchers · ₱60.00"). A "Today by person" card sits on top. Filters: dates, person, type.
- The database writes the log by itself (triggers), so the sell, void and import code is untouched. Nobody can edit or delete a log row. Unsold codes are never written to the log, sold codes are masked (`***275`), guest names are not logged.
- A small hardening fix: a deactivated staff member can no longer read old payment rows.
